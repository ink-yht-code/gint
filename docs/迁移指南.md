# 迁移指南（旧版 -> 当前版本）

本文用于说明从旧版文档/模块迁移到当前版本时的主要变化。

## 文档结构调整

旧版中分散在各目录的文档，已统一收敛到 `docs/` 目录，并按主题分类：

- 核心功能：`docs/核心功能/*`
- 认证授权：`docs/认证授权/*`
- 中间件：`docs/中间件/*`
- 微服务支持：`docs/微服务支持/*`
- 数据层：`docs/数据层/*`
- 服务治理：`docs/服务治理/*`
- 开发工具：`docs/开发工具/*`

建议统一从 `docs/README.md` 进入查看。

## 旧文档路径映射

常见迁移如下（非完整列表）：

- `docs/参数校验.md` -> `docs/核心功能/参数校验.md`
- `docs/Handler包装器.md` -> `docs/核心功能/Handler包装器.md`
- `gctx/docs/Context增强.md` -> `docs/核心功能/Context增强.md`
- `docs/响应码规范.md` -> `docs/核心功能/错误处理.md`
- `session/docs/Session管理.md` -> `docs/认证授权/Session管理.md`（推荐入口）

## 权限模块变更

旧版 `casbin` 目录及相关文档已移除，当前版本不再内置 Casbin 适配层。

如需权限控制，建议采用以下方式：

- 认证层：使用 `middlewares/auth` 完成身份鉴权与用户上下文注入
- 授权层：在业务层或统一中间件中实现 RBAC/ABAC 规则判断
- 外部策略引擎：按需自行集成 Casbin 或其他权限组件

## 推荐升级步骤

1. 先替换所有旧文档链接为 `docs/README.md` 下的新路径
2. 对照 `docs/认证授权/认证中间件.md` 更新认证接入方式
3. 对照 `docs/核心功能/错误处理.md` 统一错误码与错误返回
4. 若历史代码依赖 `casbin` 包，先拆分权限判断逻辑再迁移到新方案

## 兼容性建议

- 在升级窗口期内，建议保留一层项目内部适配代码，避免业务代码一次性大改
- 对认证、授权、错误处理相关路径补充回归测试
- 优先保证网关链路与下游服务间 header 透传行为一致
