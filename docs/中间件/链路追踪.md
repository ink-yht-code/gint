# 链路追踪中间件

链路追踪中间件用于记录请求的调用链路，帮助排查性能问题和错误。

## 兼容性说明

- 当前版本使用 `trace.Middleware()`
- 不存在 `trace.NewMiddleware()` 与独立 `Config` 结构

## 功能特性

- 支持自定义追踪ID生成
- 自动在请求头中传递追踪ID
- 支持跨服务调用的链路追踪
- 与日志系统集成，统一追踪上下文

## 使用示例

```go
package main

import (
    "github.com/gin-gonic/gin"
    "github.com/ink-yht-code/gint/middlewares/trace"
)

func main() {
    r := gin.Default()
    
    // 使用链路追踪中间件
    r.Use(trace.Middleware())
    
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(200, gin.H{
            "message": "pong",
        })
    })
    
    r.Run(":8080")
}
```

## 头字段约定

- Trace：`X-Trace-ID`
- 用户：`X-User-ID`、`X-User-Role`、`X-Tenant-ID`、`X-Username`、`X-Email`

## 跨服务调用

在服务间调用时，中间件会自动在请求头中添加`X-Trace-ID`，下游服务可以通过该头获取追踪ID：

```go
func downstreamHandler(c *gin.Context) {
    traceID := c.GetHeader("X-Trace-ID")
    // 使用traceID进行日志记录
}
```

也可以在服务端主动将 `gctx.Context` 注入到下游请求：

```go
req, _ := http.NewRequest(http.MethodGet, "http://downstream/api", nil)
trace.InjectGctx(ctx, req)
```
