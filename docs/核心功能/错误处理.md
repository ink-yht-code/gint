# 错误处理

`gint` 使用统一的 `code / msg / data` 响应结构，并通过 `BizError` 表达业务错误。

## 响应结构

```json
{
  "code": 1001,
  "msg": "用户不存在",
  "data": null
}
```

## 业务错误（BizError）

```go
type BizError struct {
	Code  int
	Msg   string
	Cause error
}
```

## 创建业务错误

```go
err := gint.NewBizError(1001, "用户不存在")
err = gint.NewBizError(1001, "用户不存在").WithCause(dbErr)
```

## 常见框架错误码

```go
const (
	CodeSuccess            = 0
	CodeBadRequest         = 400
	CodeUnauthorized       = 401
	CodeForbidden          = 403
	CodeNotFound           = 404
	CodeMethodNotAllowed   = 405
	CodeConflict           = 409
	CodeTooManyRequests    = 429
	CodeInternalError      = 500
	CodeNotImplemented     = 501
	CodeBadGateway         = 502
	CodeServiceUnavailable = 503
)
```

## 示例

```go
func (s *UserService) GetByID(id int64) (*User, error) {
	user, err := s.repo.FindByID(id)
	if err != nil {
		if errors.Is(err, gorm.ErrRecordNotFound) {
			return nil, gint.NewBizError(1001, "用户不存在")
		}
		return nil, gint.NewBizError(gint.CodeInternalError, "查询失败").WithCause(err)
	}
	return user, nil
}
```

## 包装器行为

- `error == nil`：正常写出 `gint.Result`
- `BizError`：按业务错误返回
- `gint.ErrUnauthorized`：映射为 `401`
- `gint.ErrNoResponse`：跳过自动响应写出

## 建议

- 低位区间保留给框架错误码
- 业务错误码按模块分段
- 原始错误保留在 `Cause` 中方便日志追踪
- 面向用户的 `Msg` 要稳定清晰
