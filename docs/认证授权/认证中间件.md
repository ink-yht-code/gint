# 认证中间件

`middlewares/auth` 提供基于 JWT 的认证中间件，并可选结合 `session.Provider` 构建完整用户上下文。

## 可用中间件

- `auth.Middleware`：强制认证，失败返回 `401`
- `auth.GatewayMiddleware`：网关场景认证，注入用户头用于下游透传
- `auth.OptionalMiddleware`：可选认证，无 token 或无效 token 时放行

## Config

```go
type Config struct {
    JWTManager      jwt.Manager
    TokenExtractor  TokenExtractor
    SessionProvider session.Provider // 可选
}
```

说明：

- `JWTManager` 必填（`OptionalMiddleware` 除外，未配置时会直接跳过）
- `TokenExtractor` 可不填，默认 `BearerExtractor()`
- `SessionProvider` 可不填，默认走全局 `session` provider

## Token 提取器

- `auth.BearerExtractor()`：从 `Authorization: Bearer <token>` 提取
- `auth.HeaderExtractor("X-Token")`：从指定 header 提取
- `auth.CookieExtractor("token")`：从 cookie 提取

## 标准认证示例

```go
import (
    "time"

    "github.com/gin-gonic/gin"
    "github.com/ink-yht-code/gint/jwt"
    "github.com/ink-yht-code/gint/middlewares/auth"
)

opts := jwt.NewOptions("secret", 2*time.Hour, 7*24*time.Hour)
manager := jwt.NewManager(opts)

r := gin.Default()
r.Use(auth.Middleware(auth.Config{
    JWTManager: manager,
}))
```

## 网关模式示例

`GatewayMiddleware` 在认证成功后会写入以下 header（请求头 + 响应头）：

- `X-User-ID`
- `X-User-Role`
- `X-Tenant-ID`
- `X-Username`

```go
r.Use(auth.GatewayMiddleware(auth.Config{
    JWTManager: manager,
}))
```

## 业务中读取用户信息

认证成功后，可从 `gctx.Context` 读取：

```go
r.GET("/profile", gint.W(func(ctx *gctx.Context) (gint.Result, error) {
    return gint.Success("", gin.H{
        "user_id": ctx.UserId(),
        "role":    ctx.Role(),
    }), nil
}))
```

## 常见问题

- **`JWTManager` 为空会怎样？**  
  `Middleware` 与 `GatewayMiddleware` 会返回 `500`（配置错误），不会 panic。

- **只想“有 token 就解析，没 token 也放行”？**  
  使用 `OptionalMiddleware`。
