# 认证中间件

`middlewares/auth` 提供基于 JWT 的认证中间件，并可选结合 `session.Provider` 构建更完整的用户上下文。

## 可用中间件

- `auth.Middleware`：强制认证，失败返回 `401`
- `auth.GatewayMiddleware`：网关模式认证，适合向下游透传用户信息
- `auth.OptionalMiddleware`：可选认证，没有 token 时也允许继续访问

## 配置

```go
type Config struct {
	JWTManager      jwt.Manager
	TokenExtractor  TokenExtractor
	SessionProvider session.Provider
}
```

说明：

- `JWTManager` 是严格认证场景下的核心依赖
- `TokenExtractor` 不传时通常默认走 Bearer Token
- `SessionProvider` 不传时通常回退到全局 Session Provider

## 令牌提取器

- `auth.BearerExtractor()`
- `auth.HeaderExtractor("X-Token")`
- `auth.CookieExtractor("token")`

## 标准示例

```go
opts := jwt.NewOptions("secret", 2*time.Hour, 7*24*time.Hour)
manager := jwt.NewManager(opts)

r.Use(auth.Middleware(auth.Config{
	JWTManager: manager,
}))
```

## 网关示例

```go
r.Use(auth.GatewayMiddleware(auth.Config{
	JWTManager: manager,
}))
```

认证成功后，网关模式通常会写入这些 Header：

- `X-User-ID`
- `X-User-Role`
- `X-Tenant-ID`
- `X-Username`

## 读取用户信息

```go
r.GET("/profile", gint.W(func(ctx *gctx.Context) (gint.Result, error) {
	return gint.Success("", gin.H{
		"user_id": ctx.UserId(),
		"role":    ctx.Role(),
	}), nil
}))
```

## 建议

- 需要强制登录的接口使用 `Middleware`
- 需要“有 token 就解析、没 token 也放行”的场景使用 `OptionalMiddleware`
- 需要同时使用 JWT 与 Session 状态时同时配置 `JWTManager` 和 `SessionProvider`
